## R14 · 2026-08-31 · 页面级校验进 CI；两个由此暴露的真实缺陷

**动机是实测出来的，不是推测。** 往 `applyTransforms` 注入一个必然白屏的语法错误，
然后跑一遍 CI 会跑的全部步骤：`npm test` 退出码 0、`build_site.mjs` 退出码 0 ——
**CI 全绿，然后把白屏发布出去。** 页面的 JS 从头到尾没有任何一步解析过。
这不是假想：本会话已踩过两次同类错误（暂时性死区、函数头被重复插入），
两次都只因恰好手动打开了页面才发现。

两层：

- `check_page.mjs`（并入 `npm test`，一秒、零依赖）：模块脚本语法、
  JS 引用的 DOM id 是否都有定义（这个差集此前每次改 DOM 都靠手工核对）、
  `__SITE_URL__` 占位符是否还在。三条都验过能失败。
- `test_page.mjs`（CI 起无头浏览器，约 18 秒）：三模型 × 桌面/移动两视口跑
  五个 `__verify*`，加深链往返（真实重载），**再加每条校验的对照组** ——
  清空署名、制造重叠、缩窄衬底、掉转发射方向、打乱 manifest 绑定，
  破坏后必须报错。只验「通过」的话，一个恒真的检查会永远显示绿色。

**这套东西一上来就抓到三件事：**

1. `site/index.html` 里躺着一个真实的语法错误 —— 正是前面做实验注入的那个。
   我还原了 `web/index.html` 却没重建 `site/`，构建产物带着白屏放了一整段时间，
   在此之前没有任何东西发现得了。
2. **URL 回写用防抖是错的。** 相机的缩放与对焦点逐帧渐近插值，OrbitControls
   因此几乎每帧发 `change`，防抖被无限顺延 —— 场景动着的时候 URL 永远不写，
   `LINK` 可能复制到一条过期地址。之前手动测能过，是因为恰好采样在静止时刻。
   改成节流（首次调用即排期，窗口内忽略后续）。
3. **agent 命令绕开了 URL 回写。** `setExplode` 直接改 state，
   `window.__setMode` 更是 `setMode` 的一份副本、只少了回写那一行 ——
   正是「两条路慢慢分叉」的实例，而我当初抽出 `setMode` 就是为了防这个。
   四条爆炸路径与两条模式路径已收敛到单一入口。

**测试自己的断言先错了两次，都是 CI 才暴露的**（本机快，两次都能蒙混过关）：

- 往返比较用了逐字相等，而 az/el 是连续量、经 URL 取整往返，本来就不该逐位相等。
- 更根本的一条：判「往返一致」不该依赖动画收敛。CI 用软件渲染 54 万面，
  帧率只有几帧，等场景停稳必然超时（20 秒都不够），而失败时快照其实是被采样在
  补间中途 —— 除 az/el 外所有字段都对。
  改成**拿 URL 自身当基准**：等 URL 写出参数 → 解析出期望值 → 重载 → 比对。
  写链接那一刻相机是否还在动，就与要断言的性质无关了。
  容差会把比较变成恒真，所以「改掉参数后必须比出不同」也写进了测试。

**踩到的**：`test_page.mjs` 第一版把 `chromium.launch()` 写在 `try` 外面，
launch 一失败服务器就泄漏，下次运行直接撞 EADDRINUSE，而当时只报「启动超时」——
把真正的错误吞了。已改为服务器一定回收，且启动失败会带出 stderr。
同类问题：模块级语法错误走 `pageerror` 不进 `console`，只听 console 的话
白屏表现为干等 90 秒。现在超时会直接说出原因。

## R13 · 2026-08-30 · 重复体标签一致性；借此修掉子串匹配缺陷

R12 里发现 `MATERIAL_HINTS` 的 `"face"` 子串会命中 `"aiStandardSurface"`，
但当时**没有修**，因为直接修会更糟：samurai 的镜像件里只有其中一件的材质带着
`before_duplicating_helmet` 前缀，去掉误命中只会让另一件掉回位置判定，
把一对几何完全相同的零件劈成两个标签。

这一批先立不变量，再修匹配：

> 三角面数与尺寸完全相同的零件，必须拿到相同的部位标签（`side` 可以不同）。

裁决用多数决，平局退回纯位置判定 —— 几何相同则位置判定必然相同，分歧只可能来自
材质名这类非几何证据，而只作用于孪生件之一的证据本身就可疑。
实现排在对称配对之后、人工覆盖之前。

**两处对照都验过：** 停用不变量，samurai 那一对立刻裂成 `helmet` / `neck`；
回归测试里故意改坏一组标签，检查必须报错（否则它是恒真的）。

**顺带修对了一处分类。** samurai 的 node 54/56 由 `helmet` 变为 `neck`。
原先的 `helmet` 完全建立在两个虚假信号上（一件靠组名残留，一件靠 `surface` ⊃ `face`）。
渲染核对：`helmet/C` 是兜 —— 金色前立、鬼面、面颊与颚部；这两件是悬在兜下方
84% 高度的层叠弧形甲片，即𩊱（颈甲）。所以这次是修对了，不只是修一致了。
证据留在 `shots/samurai-kabuto-helmet.png` 与 `samurai-shikoro-neck.png`。

hulkbuster 与 ironman 分类零变化；samurai 组数 10 -> 11。

**R12 朝前判定：核对真值后删了两条启发，而不是补第四条。**
原计划是加第四条。先做了实证：候选 helmet-vs-chest 在 ironman 上给出**错**答案，
差额只有身高的 0.4%（噪声）。顺着查下去发现更严重的问题 —— 用三个模型的真值
（从 +z 渲染正视图确认，都朝 +z）核对现有三条：

| 启发 | hulkbuster | ironman | samurai |
|---|---|---|---|
| face 材质 | +1 ✓ (1.19%) | 不可用 | 不可用 |
| helmet vs neck | −1 ✗ (−0.74%) | +1 ✓ (3.09%) | −1 ✗ (−5.02%) |
| foot vs shin | −1 ✗ (−4.76%) | +1 ✓ (3.01%) | 不可用 |

后两条错多于对，只因在 hulkbuster 上被 face 材质压住才没暴露。
**调阈值救不了**：samurai 上 helmet-vs-neck 以 5.02% 的差额给出错答案，比 face
材质给出正确答案时的差额还大 —— 差额大小与正确性无关，是判据本身不成立。已删除。
三个模型 frontSign 都不变（本来都是 +1），变的只是 ironman 不再声称有依据。

**踩到的：一次险些扩大的修复。** 途中发现 `"face"` 子串会命中 `"aiStandardSurface"`
（samurai 上 5 件被误指为头盔）。朝前判定那处改成整词匹配是干净的；但同样改
`MATERIAL_HINTS` 时发现，node 56 与另一件 h、三角面数完全相同的孪生件是重复体，
只有其一带 `before_duplicating_helmet` 前缀 —— 修完会**把一对完全相同的零件劈成
两个标签**，比两个都错得一致更糟。已回退该处，只留证据与理由。
左右对称配对救不了这种情况：两件都在中线附近，不构成 L/R 对。

## R9 · 2026-08-29 · REPULSOR；CI 补齐第三个模型

- **CI 的 manifest 可复现性检查补上 samurai。** 此前只跑 hulkbuster 与 ironman，
  恰好漏掉当初用来做泛化检验的那个。补之前先在本地确认它用默认参数就能逐字节复现。
- **REPULSOR。** 发射口是**推导**出来的，不是标注的 —— 模型里没有任何
  「这里是掌心」的语义。取臂链（shoulder → upper_arm → forearm → hand）
  最远的那一节，方向取「上一节 → 这一节」，发射口落在该节沿此方向的最远角点。
  与姿态无关，手臂垂着还是举着都成立。
  - **不能写死在 `hand` 上**：三个模型的臂链长度都不一样 —— hulkbuster 两侧到 hand，
    samurai 只有左手，**ironman 一个 `hand` 组都没有**，右臂只分离到 upper_arm。
  - 要求末端至少到 forearm，否则该侧不开火。ironman 因此只有左手能发射，
    按钮与 `playRepulsor` 都会明说原因，而不是静默无动作。
- **刻意不引入后处理。** 加 EffectComposer / UnrealBloomPass 会改变渲染路径，
  而 HUD 上的 DRAW CALLS 与 TRIANGLES 是如实读 `renderer.info` 的。
  为一个特效让那两个读数失真不值得。改用叠加混合的 sprite + 点光源 + 射流网格，
  实测三个模型开火时都稳定 120fps，draw call 只多 4 个。

**踩到的三件事，都是「看起来没错但读起来不对」：**

1. **点光源把整具装甲照白。** `intensity=7 / distance=0.9H` 时胸口的红被冲成粉，
   像过曝而不是发光。压到 `0.5 + 1.7 flash / distance=0.4H`，闪光改由 sprite 承担。
   失败态留档 `docs/shots/repulsor-washout-fail.png`。
2. **叠加发光被 ACES 压成灰蓝。** 渲染器开着 `ACESFilmicToneMapping`，
   叠加上去的 0.5 左右会被压回灰色 —— 射流看着像根灰杆子。
   发光材质设 `toneMapped = false` 绕开色调映射才能保住饱和度。
3. **等粗的细长圆柱在正交投影下就是一根杆子。** 改成向远端扩口，
   并用顶点色沿长度衰减（叠加混合下「趋于黑」即「消失」），远端才不是一刀切的断面。

**差点又栽在失败无声上**：`__verifyRepulsor` 第一版写了两条判据 ——
「发射口要在朝外一端」和「离末端组不能太远」。事后发现**两条都恒真**：
发射口由 `center + dir × reach` 构造，而 reach 是包围盒角点投影的最大值，
必然非负且必然不超过半对角线。已换成两条真能失败的：
发射口必须比末端组中心更远离躯干（方向取反即失败）、射流不得指向躯干内部。
配套 `__scrambleRepulsor('flip'|'center')` 作对照组，三个模型上都能让校验变红。

**一处意外的交叉验证**：后坐位移在 `applyTransforms` 走父节点局部空间、
在 `__verifyManifest` 走场景空间再换算到世界空间，是两条独立路径。
峰值时零件实际移动 0.049 身高，而 `maxDeviation` 仍是 2e-6 ——
两条路径在四位小数上一致，等于验证了 `toLocal` 那个矩阵映射是对的。

## R4 · 2026-08-28 · 仓库转公开 + Pages 上线

`242341e` `2e73d01`

- **为什么从 private 转 public**：GitHub Pages 在免费计划的私有仓库上不可用；
  更关键的是**仓库可见性保护不了模型** —— 一旦部署到任何公开站点，
  GLB 就是公网可直接下载的。所以「private 仓库 + 公开 Pages」自相矛盾。
  评估过 Cloudflare Pages（免费、可保持仓库私有）与 Cloudflare Access
  （唯一能真正不公开资源的方案），最终选了最简单的公开路径。
- **公开前重写了 git 历史**，移出两份文件：一份是个人对话记录，
  一份含对具体上传者的来源推断（点名的公开指控）。二者仅留本地，已入 `.gitignore`。
  只从 HEAD 移除不够 —— 内容仍在历史里。这是**唯一干净的时机**（当时无 fork 无 star）。
- 提交者邮箱按用户选择保留为真实地址。

**踩到的**：`--force-with-lease` 报 stale info —— `filter-branch` 连本地的
`origin/main` 引用一起重写了，租约期望值失效。需先 `git fetch` 同步真实远端状态。
