# 爆炸图设计记录

2026-08-27

## 出发点：径向爆炸为什么失效

第一版用 `explodeDir = normalize(部件中心 − 身体中心)`，实测几乎无效：

| 模式 | ironman 组级可见分离 | hulkbuster 组级可见分离 |
|---|---|---|
| radial | 3/19（中位间隙 0.16） | **0/24**（中位间隙 0.03） |

根因有两层。

### 第一层：径向场在局部无散度

从单一中心出发的单位径向场，在局部近似为常量。相邻两件的方向几乎相同 →
位移几乎相同 → **相对位移趋近于零**。看到的是整体放大，不是拆开。

尝试过的补救和结果：
- **组质心径向 + 组内均匀膨胀**（twoLevel）：略有改善但不解决问题
- **按组尺度归一化的膨胀**：错误做法。展开后是 `d_local × L / maxdist`，
  膨胀系数被组尺度除掉，**组越大膨胀越弱**。chest 组跨度约身高 0.6，
  系数掉到 0.15，完全看不出。

### 第二层（决定性）：这些零件是嵌套互穿的壳层

实测两个模型的几何形态：

| | 最近邻中心距 / 自身对角线（中位） | AABB 重叠数（中位/最大） | 零件对角线/身高（中位/p95） |
|---|---|---|---|
| ironman | 0.32 | 7 / 33 | 0.13 / 0.38 |
| hulkbuster | **0.06** | **14 / 50** | 0.16 / **0.55** |

hulkbuster 的 147 个零件里**没有一个**与他人无重叠，相邻件中心距只有自身
对角线的 6%。

**任何基于质心位置的位移场，对中心几乎重合的零件必然给出几乎相同的位移。**
这不是参数问题，是方法问题。

### 第三层：147 个零件做单层爆炸图本身是错的

回看参照页面（yadongxie.com/lab/tanks）的遥测面板，上面写的是 `GROUPS / FPS`
—— 它爆炸的是 drawing group，不是单个 mesh。坦克拆成 6–10 组，不是 147 片。

## 采用的方案

**按语义组作刚体整块分离**，组内保持相对位置。

```
位移 = 语义组轴(部位, 左右) × 链式距离(部位)          [+ 组内按秩等距展开]
```

- **语义组轴**定义在规范坐标系 (U=上, O=横向朝外, F=朝前) 中，**来自部位语义
  而非几何位置** —— 这是与姿态解耦的关键
- **链式距离**沿运动链递增（chest 0.06 → shoulder 0.16 → upper_arm 0.26 →
  forearm 0.37 → hand 0.48，单位为身高分数），使肢体各节互相分开
- **分组键是 (部位, 左右)**，因为左手和右手是两个独立子装配体
- **组内排秩**按「远端角在组轴上的投影」= `中心·轴 + 半尺寸·|轴|`，
  使外层壳排在前面且不交叉。这是嵌套壳层唯一有效的分离依据 ——
  中心重合但外层包围盒更大

## 结果

| 模式 | ironman 组级 | hulkbuster 组级 | 足迹膨胀 (宽×高×深) |
|---|---|---|---|
| radial | 3/19 · 0.16 | 0/24 · 0.03 | 1.5 × 1.2 × 1.5 |
| **group** | **12/19 · 0.53** | **6/24 · 0.22 · 0 碰撞** | 2.4 × 1.6 × 1.5 |
| groupSpread | 10/19 · 0.42 | 9/24 · 0.24 | 2.9 × 1.9 × 2.2 |

## 意外发现：语义爆炸是一个姿态归一化器

hulkbuster 的原始姿态是前倾出拳，我此前判断"姿态问题无法用代码绕过"。

**这个判断被推翻了一半。** 因为每个组都被送到语义上应有的位置（头盔向上、
双臂横向、双腿向下），爆炸态下它呈现为完全对称的直立技术图版。
见 `shots/hb-front45.png` —— 正交 FRONT + 45% 爆炸。

准确表述：**装配态（t=0）仍是弓身的，爆炸态被归一化了。**
所以对这个模型，部分爆炸态才是主视觉 —— 这也解释了参照页面为什么
默认显示 `EXPLODE 38%` 而不是 0%。

这个性质有回归测试保证（`scripts/test_explode.py`）：同一套装甲在直立与
弓身两种姿态下，语义组轴向的最大方向偏差为 2.22e-16（浮点精度）；
对照组 radial 有 19/21 个部件方向漂移，证明该测试非空。

## 指标设计

只测「是否分开」会导致过度分散。实际用两个互相制衡的指标：

1. **净间隙 / 单元自身包围盒对角线** ≥ 0.35 才算看得出分开，< 0 为碰撞。
   用自身尺度归一化是必需的 —— 20 单位宽的零件挪开 5 单位是看不见的。
2. **足迹膨胀**，2 倍左右为宜。第一版距离取大了一倍，足迹达 5 倍，
   渲染出来像碎片散落（`shots/im-groupspread.png` 是当时的失败记录）。

刚体分组模式必须看**组级**指标 —— 组内零件是有意保持相对位置的，
用逐件指标评判它会得出错误结论。

## 运行时要点

- 位移向量单位是「模型高度的分数」，运行时 `pos = base + vec × 身高 × t`
- 向量自带幅度，所以**不能用 `Vector3.transformDirection()`**（它会归一化）。
  取矩阵 3×3 线性部分 `Matrix3.setFromMatrix4()` 再 `applyMatrix3()`，
  旋转与缩放一并正确带上
- 取景：把爆炸态包围盒烘进 `boundsAtFull`，运行时在装配态取景与
  完全爆炸取景之间按进度插值，不用写死的拉远系数
- 缩放必须自管（`controls.enableZoom = false`）。否则 OrbitControls 的
  `change` 事件会在取景动画过程中触发，把动画误判成用户输入，形成反馈环
  —— 这个 bug 的表现是 ORTHO ZOOM 停在 1.18 而非应有的 0.49
- 装甲是开放壳体，爆炸后大量露出背光内表面，需要一个跟随相机的补光

# 钻取交互（2026-08-28）

点选某个子装配体 → 其余幽灵化 → 该组组内展开 → 相机对焦 → 面板显示详情。

## 组内展开为什么要单独一套向量

`groupSpread` 模式把 `GROUP_SPREAD = 0.14` 身高按秩等分给组内零件。
组一大就摊薄了：39 个手指每个只分到 0.0037 身高，钻取时完全看不见。

`drill` 模式改为**按各零件在组轴上的自身厚度分配间距**，再归一化到
`DRILL_TOTAL = 0.55` 身高。大零件给大间隙，同时总量有界 ——
否则 39 个零件的组会拉成一条无限长的线。

## 位置公式

```
非选中组: base + 组向量 × 爆炸进度
选中组:   base + lerp(组向量 × 爆炸进度, 钻取向量, 钻取进度)
```

钻取进度 d=0 时行为完全不变，d=1 时无论爆炸进度多少都到达钻取位姿。

## 运行时踩到的四个坑

1. **材质在节点间共享** —— hulkbuster 是 19 个材质配 155 个节点，直接改
   透明度会牵连其它零件。每个 mesh 在加载时克隆一份自己的材质
   （贴图按引用共享，不额外占显存）。

2. **双面透明材质会渲染两遍** —— Three.js 自 r155 起对「双面 + 透明」
   做两遍渲染（先背面后正面）。实测幽灵化 132 个网格额外产生 43.5 万面，
   渲染面数一度超过模型总面数。幽灵透明度只有 0.06，两遍的排序改善看不出来，
   设 `forceSinglePass = true`。

3. **取景用 `max(宽,深)` 会低估斜视角** —— 3/4 视角下对角方向的实际跨度可达
   1.4 倍，零件被裁到画面外。改用包围盒对角线（外接球直径），方向无关，
   用户任意旋转都不会裁切。代价是细长的组在沿其长轴观察时会偏小。

4. **拾取开销** —— 直接对 147 个 mesh、54 万面做三角形求交实测 5.7ms/次。
   加包围盒预筛（按入射距离排序 + 提前退出）降到 3.8ms，147 个零件筛出
   约 10 个候选、实际精确求交约 4 个。仍不足以支撑 25Hz 连续悬停，
   于是把悬停改成**指针停下 120ms 后才拾取一次** —— 光标反馈本来就不需要高频。
   点击路径 3.8ms 无感。

   另外必须区分点击与拖拽旋转：位移超过 5px 即判为旋转，不触发选择。

# ASSEMBLE 组装动画（2026-08-28）

## 它和「爆炸倒放」的区别

倒放是所有零件同时收拢。组装是**每个零件走自己的时间轴**：

```
位置进度 = 1 - easeOutBack( clamp((全局进度 - 该零件起始时刻) / 运动窗口, 0, 1) )
```

起始时刻在 `explode_plan.py` 里烘焙成每个零件的 `assembleDelay`，由两部分组成：

1. **组间顺序**（`ASSEMBLE_ORDER`）—— 模拟穿戴：
   脚 → 小腿 → 大腿 → 骨盆 → 腹 → 胸 → 肩 → 上臂 → 前臂 → 手 → 颈 → 头盔。
   头盔最后，那是收尾镜头。
2. **组内错峰** —— 外层壳后到，才能盖在内层上。直接复用爆炸规划里
   按「远端角在组轴上的投影」排出的秩。

左右对称件起始时刻完全相同，同时归位。

## 组内错峰必须受组间间隔约束

第一版把组内错峰定为固定的 0.06，而组间间隔是 0.058 —— 回归测试立刻抓到：
胸甲最外层在 0.351 起步，晚于肩甲的 0.349。而肩甲是盖在胸甲上的，顺序反了。

改为 `intra = min(ASSEMBLE_INTRA, 组间间隔 × 0.8)`，保证组顺序不被组内错峰突破。
测试里逐对断言了完整穿戴序列，以及「靴子最先、头盔最后」。

## 相机与位置解耦

取景仍由全局进度驱动（`explode` 从 1 平滑收到 0），位置由逐零件时间轴驱动。
这样相机随装配自然推近，不需要单独写一套镜头运动。

## 发光收尾

组装期间把发光强度压到 0，最后 18% 用 smoothstep 拉起 —— 反应堆与眼缝点亮
作为落点。发光材质有两个来源：manifest 标记的（hulkbuster 的 `light` 系材质）
与自带 emissive 贴图的（ironman 的反应堆），统一按基准强度缩放。

## 一个反复出现的教训

`str.replace` 不匹配时静默跳过。这次插入 MOTION 遥测行时缩进写错（4 空格 vs 2），
替换无声失败，`$('mo')` 拿到 null，整个模块脚本在首帧崩掉。

这是本项目第三次栽在「失败无声」上（前两次：LFS 空文件误报、爆炸为 0 时恒真的
manifest 校验）。此后所有补丁脚本都带匹配断言，并在改完后核对
「JS 引用的 DOM id」与「HTML 定义的 id」两个集合的差集。
